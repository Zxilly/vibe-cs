# Vibe CS 双模式 UI 重设计计划

状态：用户于 2026-09-06 确认方案；Figma 基础、组件及 10 个代表性流程画板已更新，生产 UI 已完成实施。最终验证与设计规范见文末。

## 已确认的产品方向

用户要求先对齐 Figma 与本地，再基于 Figma 设计系统重设计整个 UI，最后更新代码。浅色蓝灰、统一且清晰；剪辑模式服务创作者，分析模式服务数据分析。保留已有功能和唯一的数据/编辑权威。

源码基础为 `apps/web/src/design/theme.css`，Figma 为 `N05FPVtPTwWV3ONlE48Fwv`。

- Figma 已有 3 个变量集合、133 个变量、17 个文本样式、3 个效果样式。

- 文件没有已订阅外部组件库；对 PanelHeader、color、spacing 的库搜索为空。直接读取已存在的本地组件和变量仍成功，搜索为空不代表文件没有设计系统。
- 未发现 Code Connect 文件。本轮先保留变量到 CSS 的映射，不假称已完成组件映射。
- 初始对齐修正了编辑器与导出背景中 64 个素材行宽度。后续已完成截图复核、Agent 阅读字级和容器校准；这些初始测量不作为最终布局常量。

## P0.d–P0.f：已确认的统一规则

| 角色 | 当前问题 | 提议 |
|---|---|---|
| 字体 | 本地 system-ui/Consolas 与 Figma Noto Sans SC/Roboto Mono 不同 | 使用 Figma 的 Noto Sans SC 和 Roboto Mono；本地随应用提供所需字重，避免环境字体改变换行 |
| 配色 | Shell 与 Workbench 是两套浅色灰阶/蓝色 | 以现有 Figma Workbench 蓝灰为共同基础，提升弱文字对比度；两种工作模式不再更换品牌配色 |
| 间距 | 3.4 px 基础生成大量小数，面板 chrome 又使用独立值 | 改为 4 px 基础；统一 8/12/16/24/32 px 组合 |
| 控件 | 32/34/38/42 px 高度与 Dock 标题不一致 | 小/中/大/强调控件 32/36/40/44 px；面板标题 36 px；窗口栏 48 px，页面工具栏 56 px |
| 字级 | 很多相近字号，Agent 长文沿用紧凑元数据字级 | 元数据 12 px、控件 13 px、正文 14 px、阅读正文 16 px；标题以 18/24/28 px 分级；时间码等宽 |
| 对齐 | 头部、滚动体与页脚的内容边缘各自计算 | 定义共享内容内边距和滚动条占位；标题、搜索、行文本、底部操作采用同一内容轴线 |
| 状态 | 普通 ghost 动作长期着蓝色，与主动作竞争 | 默认普通动作使用中性色；蓝色用于主动作、当前选择和键盘焦点；危险动作与普通动作分隔 |

保留现有暗色设置能力；浅色方案是本轮主要视觉基准，暗色应从相同语义角色派生并检查，不保留页面私有调色板。

### 布局

- 剪辑：素材列 → 主要 Program 预览与辅助 Tactical 预览 → 共享 Timeline；Agent 为支持列。默认 Program 大于 Tactical，保持可停靠、可调整面板和已有键盘操作。用户自定义布局不静默清除。
- 分析：保留比赛身份及跨视图上下文；数据/事件/地图为主内容，详情 Inspector 为支持列。概览、回合、玩家、对位、道具与经济、回放与热力图、高光、Review 与注释、队伍沿用同一框架。
- 首页、Demo 库、导入、成品、设置与诊断沿用相同导航、表格、表单和反馈语言，不变成剪辑工作台的强行复制。

### 组件范围

更新现有五个组件家族及 ProjectTimeline 模块。补齐当前产品真实重复使用的窗口/模式导航、导航项、面板标题/工具栏、表格行/表头、对话框/详情容器；不引入独立 UI 框架或通用工作流引擎。

沿用现有 Figma 三页结构，以清楚的 Section 组织新增家族与方案，不新建一套无关的大型组件库。

## 执行与验收流程

1. 确认上述基础规则后，更新 Figma variables/styles 和组件，先做剪辑与分析代表性画板，再覆盖其余现有页面及必要状态。
2. 更新现有生产组件和主题，删除被替代的页面私有视觉规则；不创建第二份产品实现。
3. 同视口、同路由、同数据与滚动状态比较 Figma 和本地；测量内容轴线、文字换行、控件大小、滚动条占位。
4. 回归两模式导航、真实分析上下文、播放/定位、时间轴键盘操作、选择与读写保护；不以静态截图代替行为测试。
5. 按 Impeccable 执行有界视觉检查和收尾评审，再从实际落地结果记录 DESIGN.md。

当前不改变原始 Demo、媒体、已有 r12 项目内容或导出成片；未执行新录制/导出，未提交或推送代码。

## 实施结果

- 统一浅色蓝灰和暗色语义主题、随包分发的 Noto Sans SC / Roboto Mono、4 px 间距基础、控件及标题高度、弱文字对比度与主次动作状态。
- 共享窗口/模式导航、面板标题、表格、表单、对话框与反馈语言已落地；剪辑以 Program 与 Timeline 为主，分析以真实数据与证据为主。继续使用现有 Timeline、Transport、Editing Document 与 Agent 权威。
- Figma 保留原始参考与旧画板；新方案涵盖剪辑、分析、首页、Demo 库、导入、高光、回放、加入作品、导出设置、成品，共 10 个代表性流程画板。不是每个路由/瞬时状态的穷举截图，也不声称逐像素相同。
- 回放楼层选择在实际 6 楼层数据下由溢出分段按钮改为已有紧凑下拉框；保留全部选项与热力过滤行为，Figma 两处对应控件同步更新。
- 实机截图覆盖 1440×900 浅/暗色剪辑与分析，以及 1100×760 桌面窄窗口；另检查资料库、导入、回放、设置、首页、成品、导出设置。截图与独立收尾报告保存在 `apps/web/.impeccable/review/`。
- 最终全量前端测试：3025 通过，0 失败；lint、TypeScript、分层检查及生产构建通过；中英各 1955 条文案，英文缺失 0。仍有 ProjectWorkspacePage 超过 500 kB 的分包提示。楼层回归先验证失败再修复通过。静态截图不替代播放、编辑与导出行为验证，未在用户真实项目执行破坏性快捷键或新录制/导出。
- 独立收尾审查唯一列出的楼层控件问题已复审解决（disposition: ship）；该结论针对审查证据与列出的修复项，不是对所有产品状态无缺陷的保证。
- 已保留用户自定义 Dock 布局；新的 Program 较大默认比例仅用于新布局或显式“重置布局”，不会静默覆盖现有偏好。
