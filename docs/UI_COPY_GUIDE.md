# UI 文案规范

本规范适用于所有用户可见文字：页面标题、按钮、状态、空态、错误、工具提示、Agent 对话投影、HITL 和可访问名称。数据模型、IPC 字段、日志与代码注释不在范围内。

规则参考项目既有的任务导向规范，以及 [`humanizer-zh`](https://skills.sh/op7418/humanizer-zh/humanizer-zh) 的直接、具体、少铺垫原则。后者用于去掉公式化表达，不用于把剪辑术语改成口语。

## 写法

1. 先说结果，再说影响和下一步。
   - `CS2 没有启动，视频尚未生成。检查游戏路径后重试。`
   - 不写 `操作失败，请检查相关配置。`
2. 按用户任务命名。
   - `导出成片`、`录制片段`、`清理暂存成片`
   - 不写 `执行录制计划`、`清理输出对象`
3. 按钮使用短动词；说明文字不重复按钮。
   - `重新分析`、`打开设置`、`拒绝`
4. 直接称呼用户为“你”，不要写“人类”“操作者”或“用户”。不需要称呼时省略主语。
5. 一句话只承担一个主要信息。删除宣传性形容词、空泛总结、聊天套话和无来源的判断。

## 统一术语

| 对象 | 使用 | 不使用 |
| --- | --- | --- |
| Agent 生成的编辑计划 | 剪辑单 | 方案 |
| 一次可撤销编辑 | 修改 | 变更 |
| Agent 聊天记录 | 对话 | 会话 |
| 时间线内容单元 | 片段 | 镜头 |
| 编辑项目 | 作品 | 工程、合辑 |
| 可交付文件 | 成片、成品文件 | 输出 |
| 后台执行记录 | 后台任务 | 任务记录 |

“镜头”可用于摄影机运动和镜头路径；“输出”可用于工具输入/输出等技术配对。不要机械替换不同含义的同形词。

## 技术词

- 普通界面隐藏 `Project Head`、`revision`、`Delivery Gate`、`Change Group`、`runtime`、`bridge`、`sidecar` 和 `JSON object` 等实现名。
- `Agent`、`Demo`、`CS2`、`Steam`、`API`、`MP4`、`H.264`、`T/CT`、`tick`、`In/Out` 等产品或领域名可以保留。
- HLAE、SHA-256、编码器探测等细节只出现在“高级与诊断”；录制确认页称为“采集组件”。
- Premiere 风格的时间线术语可以保留，但中文界面优先使用常见中文名，例如“修剪模式”“修剪”“波纹删除”。

## 状态与风险

- 进行中：`Agent 正在编辑 · 你暂时只能查看`
- 等待确认：`还没有开始导出，等你确认。`
- 完成：`成片已生成。`
- 空态：说明为什么为空，并提供一个可执行动作。
- 错误：说明哪一步没有完成、哪些内容未受影响、下一步去哪里处理。
- 删除与覆盖：写清对象、是否可恢复，以及不会删除什么。

## 交付前检查

- 文案是否直接回答“发生了什么”？
- 按钮是否描述按下后真正发生的动作？
- 是否泄漏内部类型或接口名？
- 同一对象是否用了两套名字？
- 能否删掉开场白、重复解释或空泛结论？
- 中文读出声是否自然，标点和句子节奏是否顺畅？
