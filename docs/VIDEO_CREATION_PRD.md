## 当前范围（用户于 2026-09-05 收敛）

用户明确指出字幕等包装属于过度设计。本轮目标是剪出真实、可用的 NiKo 三分钟集锦，而不是建设通用视频包装系统。以下当前需求取代此前目标中关于字幕、片头片尾、图形、配乐和旁白组件的强制要求；后文迭代日志仅保留历史事实，不构成继续开发这些能力的任务。

只推进 Demo 选材 → POV/必要的复杂 HLAE 镜头 → 录制与补录 → 时间轴剪辑和预览 → 保留游戏原声 → 导出及实际音画检查。复杂 HLAE 能力保留，但不为凑组件强制每条集锦使用。不得因包装组件未完成阻塞交付，也不再为包装继续制造测试素材或验收项目。已有测试资产和输出不擅自删除。

## 用户问题

用户有比赛 Demo 和一个创作目标，例如“制作 NiKo 的 3 分钟集锦”。他需要完成选材、镜头设计、录制、剪辑、审阅和导出。只把一个待录片段放到时间轴上不算完成；单个编辑按钮能工作，也不能证明输出正确。

## 产品结果

一个人可以独立完成制作，也可以随时让 Agent 接手。在同一个 Project 中保留全部证据、Capture Intent、Take、Timeline Placement、修改记录和输出结果。用户始终能回答：现在看到哪一版、哪些镜头没录、修改影响什么、下一步做什么、生成的文件在哪里。

首条验收影片以用户提供的 FURIA vs Falcons 三场 Demo 为来源，主角 NiKo，目标 03:00，1080p/60fps。短片只用于复现和验证明确的录制/导出缺陷，不再扩成另一套组件项目。选择镜头根据实际比赛证据，不填造战绩和回合。

## 用户故事

### A. 建立素材与证据

1. 作为创作者，我希望一次选择三个本地 Demo，并在导入期间继续操作，以便快速开始 BO5 合辑。验收：真实大文件不使页面退出；成功/重复/失败逐项可见；源文件不被修改。
2. 作为创作者，我希望分析完成后按 NiKo、地图和回合筛选事件，以便找到有依据的精彩操作。验收：能回到原始回合/tick；稀疏定位明确披露，不能补造轨迹。
3. 作为剪辑师，我希望从比赛回放设入出点并加入当前作品，以便手工选材无需先求助 Agent。验收：目标 Project 保留，待录 Clip 身份、选手与区间正确；无关设置不变。
4. 作为剪辑师，我希望项目素材同时包含待录镜头、已录 Take 和导入的视频/音频/图像，以便知道素材是否可用。验收：状态准确；可区分源资产和时间轴用法；搜索/筛选不丢资源。
5. 作为剪辑师，我希望同一视频或音乐可以反复取段，以便制作开场预告、正文和回放。验收：源素材插入后仍可选；插入/覆盖/快捷键一致；不要求再次导入。

### B. 组织完整故事

6. 作为创作者，我希望先安排“开场钩子→主体递进→高潮→片尾”，再精剪到三分钟，以便影片有节奏。验收：内容来自真实事件；目标时长包含转场和尾音；超时有可调整项。
7. 作为剪辑师，我希望移动、分割、修剪、替换不同长度片段，以便调整节奏。验收：Story 波纹正确，自由轨/同步锁遵循现有规则；一个手势一次修改；Undo/Redo 可还原。
8. 作为剪辑师，我希望源素材 In/Out 与节目播放头各司其职，以便取段时不打乱成片预览。验收：播放、帧步进、拖动、缩放和滚动共用 Timeline Transport；跨片段预览不闪烁。
9. 作为创作者，我希望在关键镜头上变速、定格或重放，以便突出动作。验收：源素材有足够覆盖；速度与音频处理明确；最终帧数与时长正确。
12. 作为剪辑师，我希望保留并调整游戏原声，以便枪声与动作清楚、同步。验收：片段音量和静音正确，没有削波或非预期爆音。

### C. 人与 Agent 协作

14. 作为创作者，我希望用一句话描述集锦，而 Agent 能选材、规划镜头并完成时间轴，以便得到可编辑的作品。验收：修改统一提交到当前文档，片段可见，待录与已录状态明确，不擅自添加未请求的包装。
15. 作为剪辑师，我希望说“把这几个片段压缩”“从这里开始淡入”，以便 Agent 理解我正在查看的范围。验收：本轮传入片段多选、轨道、播放头和范围的紧凑引用，按需读取完整证据。
16. 作为创作者，我希望 Agent 能设计复杂 HLAE 镜头，以便不受手工按钮颗粒度限制。验收：镜头计划可检视、可录制、可撤销；运行失败明确解释，不静默换成别的镜头。
17. 作为审阅者，我希望看懂 Agent 做了什么并撤回指定修改，以便保留自己后来做的编辑。验收：工具调用/结果/HITL在一个流里；定向撤销使用展示的 group ID；冲突不覆盖无关内容。
18. 作为剪辑师，我希望随时停止 Agent 并继续手工编辑，以便掌握进度。验收：旧事件不影响新一轮；异常不留假只读；已完成修改可撤销；继续任务保留完成工具证据。

### D. 录制、预览、交付和再修改

19. 作为创作者，我希望批准后录制待录镜头，以便获得真实画面和声音。验收：游戏配置保留；启动前校验必要依赖；使用指定选手和镜头；成功 Take 回填原 Clip。
20. 作为创作者，我希望中途失败后只补录缺失镜头，以便不浪费已完成录制。验收：成功前缀保留；失败定位到 Clip；重试不重复已兼容 Take；取消可恢复。
21. 作为剪辑师，我希望录制后继续修剪和混音，以便将可用素材变成成片。验收：覆盖范围内的 Placement 修改不要求重录；Capture Intent 变化才使 Take 过期；代理状态正确。
22. 作为创作者，我希望导出前知道未就绪的具体组件，以便一次解决问题。验收：检查实际启用内容的媒体、字体、嵌套依赖；链接到可修复位置；接受修改不宣称已生成视频。
23. 作为创作者，我希望输出三分钟 1080p/60fps MP4，并在产品里找到、播放它，以便实际交付。验收：文件存在可播放；总时长在目标一帧内；关键击杀和首尾完整，声音与镜头正确；输出关联 Project revision。
24. 作为剪辑师，我希望交付后修剪一个镜头再导出，以便快速回应反馈。验收：仅相关编辑改变，旧输出保留可辨识，新输出对应新 revision，不覆盖源媒体。

## 实现决策

- 保留单一 Editing Document、Timeline Module、Transport、Agent runtime 与 Conversation Projection。人类和 Agent 编辑粒度可以不同，修改权威相同。
- Project 素材提供可复用来源；Clip 是一次时间轴用法。Capture Intent 和 Materialization 继续独立于纯 Placement 编辑。
- 原生本地文件尽量由 Rust 从路径读取，避免大文件完整穿过 WebView；路径/格式/大小校验仍在外部输入接缝。
- 历史动作携带正确目标身份；先确认不会覆盖无关后续状态，再应用可逆修改。无意义的兼容层、第二套 Undo 和通用工作流引擎不在方案内。
- Agent 通过当前 Head 与 Workspace View State 的紧凑引用感知上下文，按需读取工具结果。工具循环不加次数上限。
- 复用现有剪辑、录制和导出能力；不为字幕、文字包装、音乐或嵌套继续扩展本轮工作。

## 测试决策与完成定义

1. 缺陷必须用实际调用接缝的红绿回归验证，保留跨步骤状态，不用每一步重建独立 fixture 掩盖组合错误。
2. 短片只验证明确缺陷，例如末次击杀被截断、补录或编码质量，不继续添加组件。
3. 完成三分钟集锦；在过程中验证人类接手、Agent 停止/继续与定向撤销、缺失片段补录。若使用复杂 HLAE 镜头，必须检查实际录制效果，不以计划 JSON 代替。
4. 检查视频解码、宽高/FPS/帧数/时长、首尾与关键击杀画面、目标选手、剪辑接缝、游戏音频及声画同步。自动检测与视觉听觉检查各自报告局限。
5. 记录预览拖动/跨片段表现和导出资源成本；只做诊断所需测量，不为此引入长期遥测系统。
6. 每个故事状态只能是待验证、失败、已修复待实机、已验收；“实现存在”不能记为已验收。真实外部执行未跑则目标不完成。
